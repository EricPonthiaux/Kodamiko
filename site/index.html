Principles

Starting from the other end

In Kodamiko, Claude is not a guest of the editor: the editor was designed for it. Three things follow.

It understands what you are looking at

Claude already knows which file is open, where the cursor is, what is selected and which errors are underlined. Type “fix this” and it knows what you mean: no more pasting code or spelling out file paths.

It acts with the editor's tools

Claude does more than suggest text. It goes to definitions, renames a function everywhere it is used, runs the build and reads the errors, shows a diff, draws a diagram — with the same tools as you. A commit, a push, a merge or a change of branch waits for your “Allow”.

You stay in control

Every change Claude makes appears before your eyes: open files reload as it edits them, and the diff marks the blocks it wrote. A snapshot of the project is taken before each prompt, and Restore the State Before a Prompt brings it all back. You delegate without risk.

Diagrams

A diagram is worth a thousand lines of terminal

When Claude explains a module, a flow or a refactoring plan, a wall of text scrolling by in a terminal is the hardest way to follow it. In Kodamiko, Claude draws instead, and the diagram becomes a space you share: you both read it, point at it and change it. The conversation goes both ways.

  • You ask, Claude draws“Draw the path of a prompt through Kodamiko.” Claude reads the code first, then writes the diagram in Mermaid or PlantUML: flowchart, sequence, class, state, data model, C4, mind map or user journey. It opens laid out, ready to read.
  • You point, Claude understandsSelect three boxes and type “merge these into one service”. Claude sees what is selected in the diagram, just as it sees the selection in a file.
  • Claude points, you see“Where does Claude wait before touching the code?” Rather than a paragraph, Claude answers by selecting the right elements in the diagram in front of you.
  • You arrange, Claude keeps itMove the boxes where they make sense to you. When Claude changes the diagram, every element keeps its place, new ones go beside their neighbors, and one Undo cancels its change.
  • From the diagram back to the code“Implement this state machine.” “Does the code still match this diagram?” Once you agree on the picture, it becomes the specification Claude works from.
  • Ready for the docsA diagram is a text file in your repository, reviewed like code, and Claude can export it as SVG or PNG for the documentation.

Agent tools

More than fifty tools in Claude's hands

An agent in a terminal reads and rewrites text. In Kodamiko, Claude works through the editor itself: the language servers, the refactorings, Git, the terminals and the diagrams. The same tools as you, with the same precision.

  • Understand the codeGo to a definition, find every reference, read a symbol's type and documentation, list the errors and warnings, and apply a quick fix.
  • Refactor across the projectRename a symbol or a file, or change a function's signature, through the language server rather than search and replace, and undone in one step.
  • Find its waySearch files, symbols and text across the whole project, and read a file's outline before opening it.
  • Drive GitStatus, history, branches, staging, merge, stash, pull and push; continue or abort a rebase; write the commit message.
  • Build and runRun the project's build and run configurations, type into a terminal and read what it prints, compiler errors included.
  • Show you its workOpen a file at the right line, show a diff, draw and lay out a diagram, and tell you when a long task is done.

Review

Follow every change, review before you commit

Open files reload as Claude edits them, and the Diff view marks the blocks it wrote. Stage by file, hunk or line, then Generate writes the commit message in the style of your history: a summary within 72 characters, and the why in the body.

Before committing, a separate, read-only reviewer goes over the staged changes. Its report opens above the diff, and each finding sits on the lines it concerns, ready to send to Claude or dismiss.

History

The history, with Claude's share in it

Commits are grouped by day. A click unfolds a commit's message in its row and shows the diff of all its files at once; the commits made with Claude carry its mark.

Search by text, author or date, or by what the changes contain, across every branch.

Editor

A professional editor, without the clutter

Over the years, editors have piled up panels, menus, settings and extensions, until using one became a skill of its own. Kodamiko makes a clean sweep: it keeps what a professional really needs, in a few clear places. And what you would once have hunted for in a menu, you can simply ask Claude.

  • Understand the codeSmart completion, live diagnostics and quick fixes, through language servers and Tree-sitter highlighting.
  • Navigate the projectDefinitions, usages and call hierarchies, an outline, find in files and a command palette.
  • Refactor with confidenceRename, change a signature, move a class — with a preview before applying and a one-step undo, and still fast on very large projects.
  • Git built inLine-level staging, history, branches, merge and rebase, pull, push and stash, and conflicts resolved in the editor, without leaving it.
  • Commit messages by ClaudeWritten in the style of your team's history, for you to review before committing.
  • Markdown and diagramsA rendered Markdown viewer and a diagram editor for Mermaid and PlantUML.

Get started

Try the pre-release

Kodamiko alpha.1.0.1 is a pre-release, the second public build. It is used every day to build Kodamiko itself, but its settings and interfaces may still change, and you will meet bugs. It is free and open source (GPL v3), and it uses your own Claude Code installation, installed and signed in, without touching its configuration.

  • Linux x86-64An AppImage: make it executable (chmod +x), then run it.
  • Windows x64Unzip it anywhere, then run bin\kodamiko.exe.
  • macOS, Apple siliconDrag Kodamiko to Applications. Macs with an Intel processor are not supported yet.

The packages are not signed yet: Windows SmartScreen and macOS Gatekeeper warn before the first launch (on macOS, open Kodamiko with right click ▸ Open). Their checksums are in SHA256SUMS.txt, on the release page.

Feedback

Found a bug? Tell us

A pre-release gets better through the problems its users report. Everything goes through the project on GitHub, in the open, except security vulnerabilities, which are reported privately.

  • Report a bugThe form asks what you did, what you expected and what happened, with your versions (Help ▸ About Kodamiko, claude --version) and your system. A screenshot helps for anything visual.
  • Suggest an ideaSay what you are trying to do and what gets in the way today; mockups are welcome.
  • Look at the known issuesYour problem may be reported already: add what you know to it rather than opening another one.
  • Report a vulnerabilityPrivately, through GitHub’s security advisories, never in a public issue.
